# ADR-0004: Source and export of the multi-agent pipeline role definitions

- **Date:** 2026-11-21
- **Status:** Accepted
- **Authors:** base-ai team
- **Ticket:** BASE-046-D1 (Epic #46)
- **Relation:** amends ADR-0001 §2.3 ("single AI source `.ai/`") for the role definitions only; ADR-0001 stays in force for everything else.

---

## 1. Context and problem

ADR-0001 §2.3 makes `.ai/` the single AI source: `ai sync` renders the rules and skills into every assistant's native files, and those files are generated artefacts carrying the `generated by base-ai` marker.

The multi-agent pipeline (Epic #46) added six role definitions in `.claude/agents/` (`planner`, `implementer`, `reviewer`, `qa`, `supervisor`, `improvement`). They are hand-written source at the root: they carry no generated marker, `ai sync` does not render them, and `ai stats` does not count them (it measures the rules, memory and skill index only). `.claude/commands/*.md`, by contrast, is generated from `.ai/skills/`.

Up to 0.8.0 this caused three gaps:

1. The published package and `base-ai init` did not ship the definitions or `docs/task-state-machine.md`, although the shipped rules and the `pipeline` skill name both.
2. Services (`src/<name>`, independent repositories) had no copy of the definitions, so the pipeline could not be invoked inside a service.
3. Nothing detected drift between the root definitions and any copy made by hand in a service.

The definitions, the `pipeline` skill and `docs/task-state-machine.md` refer to the definitions by their path `.claude/agents/<role>.md`, and the supervisor and improvement agents identify their own definition files by that path. Moving the source would change all of that content.

## 2. Decision

1. **The root `.claude/agents/*.md` files remain the hand-written, editable source** of the role definitions. Claude Code reads `.claude/agents/` natively, so the root needs no generated copy. The package and `init` ship them (direct children of `.claude/agents/` only), together with `docs/task-state-machine.md`, through one shared path predicate (`isShippedPath` in `cli/src/shipped.ts`).
2. **`ai sync` exports generated copies to services only.** For each service with `ai: inherit` whose configuration enables the `claude` exporter, it writes `src/<name>/.claude/agents/<role>.md` as:
   - the root file's frontmatter block, byte for byte;
   - the header `<!-- generated by base-ai: do not edit. Source: root .claude/agents/ -->`;
   - a blank line, the trimmed body and one final newline.

   The header goes after the frontmatter, as for `.claude/commands/`, so Claude Code still parses the frontmatter. It names the real source (not `.ai/`) and contains the `generated by base-ai` marker, so the existing overwrite protection, lock file (`.ai/generated.json`) and stale-artefact removal apply unchanged. A service with `ai: none`, or whose configuration excludes `claude`, gets no copy.
3. **Validation.** `ai sync` refuses a root definition without frontmatter, without `name` or `description`, with a `name` that does not match `^[a-z0-9-]+$`, or whose `name` differs from the file's basename, naming the file. It refuses to overwrite a hand-written file under a service's `.claude/agents/`, telling the user to delete it because the definitions are exported from the root `.claude/agents/`.
4. **The root render is unchanged.** The root source passes no roles to the exporters, so the root lock, the root generated files and the always-on token budget measured by `ai stats` do not change.

## 3. Impact

- **Operations:** `base-ai doctor` covers the service copies with no new check, because it already compares every service's rendered files and lock with `ai sync` in check mode. An edited root definition makes `doctor` report `AI artefact out of date: .claude/agents/<role>.md` for each service; a deleted one is reported as a stale artefact.
- **Security:** no new input surface beyond reading local Markdown files; invalid definitions fail fast with the file named.
- **Cost:** every Claude-enabled service carries about 200 KB of definitions; the always-on token budget is unaffected.

## 4. Consequences

- **Positive:**
  - New projects receive the six definitions and the state-machine doc; services receive the definitions, kept in step by `doctor`.
  - No content change to the definitions, the `pipeline` skill or the state-machine doc; every existing path reference still resolves.
- **Negative / trade-offs:**
  - There are now two kinds of AI source at the root: `.ai/` (rules and skills) and `.claude/agents/` (role definitions). This ADR is the record of that exception.
  - Services do not yet receive `docs/task-state-machine.md` or `templates/task/`, which the definitions refer to, so a planner run inside a service cannot initialise a task until a follow-up closes that gap.
  - A service that already has hand-made copies of the definitions makes `ai sync` fail after upgrading until those copies are deleted.

## 5. Alternatives considered

- **Move the source to `.ai/agents/` and generate `.claude/agents/` everywhere, root included.** Consistent with ADR-0001, but every reference to `.claude/agents/<role>.md` in the definitions, the `pipeline` skill and the state-machine doc would point at a generated file, and the implementer's deliverable exception and the supervisor and improvement own-ticket checks name those paths. It requires a content change to all six definitions; rejected for this change.
- **Also export `docs/task-state-machine.md` to services as a generated file.** It adds one file but the planner still fails on the missing `templates/task/`; left to the follow-up.
- **Have `service new` copy `templates/task/` and the doc once, not generated.** Closes the gap for new services only, with no drift detection; left to the follow-up.
