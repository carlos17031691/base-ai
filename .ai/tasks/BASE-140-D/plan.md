## Goal

The `task-dirs` job of workflow `ci` runs `base-ai pipeline ci` on every PR: A1 (append-only `transitions[]`), `pipeline check`, `pipeline plan` (P1 criteria, P2 lock) and the debt registration check. Today it is not a required status check, so a red run does not block a merge. Only the human's discipline stops one (BASE-140-B H12). This ticket adds `task-dirs` to the required status checks of the `protected-branches` ruleset file. It also rewords every statement that the job is not required, or that the human must not merge while it is red, so the docs, skills, exports and README describe the new gate. The ruleset only changes when the human runs the `PUT` from the runbook after merge. That step is a human/coordinator post-merge step, not an implementer step.
