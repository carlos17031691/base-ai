`evidence/` stays ignored, because `.ai/tasks/*/*` ignores the directory itself. The root `.gitignore` only adds two things after the block:
- **Legacy block.** For each of the 28 directories listed in "Baseline", two lines: `.ai/tasks/<id>/*` and `!.ai/tasks/<id>/usage.jsonl`. Their files stay local and do not show up as untracked, and their tracked `usage.jsonl` stays tracked.
- **Scratch rule.** `.ai/tasks/*.scratch/`. A dry-run copy is named `<name>.scratch`. The directory itself is ignored, so nothing inside it is re-included.

**D2 — `base-ai pipeline ci --base <ref> [--json] [--root <dir>]`** (H1). It is read-only. Its git calls go through the injected `Runner` (`spawnRunner` by default), one at a time:

| Id | Template | Purpose |
|---|---|---|
| G1 | `git -C <root> rev-parse --verify --quiet <ref>^{commit}` | The base commit. The output must be 40 hex characters |
| G2 | `git -C <root> diff --name-only -z --no-renames <sha>...HEAD -- .ai/tasks` | Changed paths, from the merge base to `HEAD` |
| G3 | `git -C <root> ls-tree -z --name-only <sha> -- .ai/tasks/<id>/status.json` | Whether the file exists at the base (empty output = absent) |
| G4 | `git -C <root> show <sha>:.ai/tasks/<id>/status.json` | The base version, at most 2 MiB |

The steps:
1. **Usage check.** `<ref>` must match `^[A-Za-z0-9][A-Za-z0-9._/-]*$`, so it cannot start with `-`. Without a valid `--base`, the command prints a usage line, exits 1 and runs nothing.
2. **Grouping.** Each G2 path `.ai/tasks/<id>/<rest>` is grouped by `<id>`, and other paths are ignored. An `<id>` outside `^[A-Za-z0-9#._-]+$` fails `D0 dir.name`. With more than 20 directories, the command halts. When no directory changed, it prints `no task directory changed` and exits 0.
3. **A1 `transitions.append_only`.** It runs when `status.json` is among the changed files. The base version comes from G3/G4, and the current version from the working tree (`readBounded`). The results:
   - no base version: `pass (new)`;
   - base present, current file missing: `fail` with `status.json removed`;
   - either version not a JSON object with a `transitions` array: `fail`, naming `base` or `head`;
   - fewer current entries than base entries: `fail` with `<m> of <n> base entries remain`;
   - otherwise, for each base index `i`: `fail` with `transitions[i] differs from the base` when the current entry is not deep-equal, by value and in any key order (H11);
   - extra entries at the end: allowed.

   The detail never shows file content.
4. **`pipeline check`.** It runs when a file the checks read (`status.json`, `plan.md`, `review-report.md`, `qa-report.md` or `decisions.md`) is among the changed files and `status.json` exists in the working tree. It is the normal `checkTask(loadTask(...))`. It fails when `ok` is false and names the failed ids (H3). When only other files changed (`usage.jsonl`, `improvement-report.md`, `evidence/`), it is `skip (no checked file changed)` (H4).
5. **Debt.** It runs only when the check ran, K16 passed and there is at least one key. It is `checkRegistration` with no `--issues`. `missing` fails, and lists the keys ready to paste. `halt` halts (H6).
6. **Exit code.** 2 if anything halted: a G1–G4 failure, the directory cap, or a debt halt. Otherwise 1 if any directory failed. Otherwise 0.
7. **Output.**
   - Text: a header `pipeline ci <sha7>: PASS|FAIL|HALT (<n> task dir(s))`, then one line per directory, `<id>: A1 <status>[ — detail]; check <ok|FAIL K…|skip>; debt <outcome|skip>`.
   - JSON: `{ schema: 1, base, outcome, halt?: { template, reason }, dirs: [{ id, files, append_only, check, debt }] }`.
   - Never printed: file content, git stderr, a URL, issue text.

The logic lives in `cli/src/pipeline-ci.ts`. It has no `node:` import, and its dependencies (runner, reader, check and debt) are injected. `index.ts` only dispatches to it. `pipeline check`, `pipeline debt`, `RULE` and K1–K19 are unchanged.

- `if: github.event_name == 'pull_request'`.
- Job-level `permissions: { contents: read, issues: read }`.
- Steps:
